## Current support

The production CLI catalog stage persists API records and classified PACKAGE/OVERVIEW narratives through the same atomic knowledge/document/section association. Narratives use narrative/1 IDs derived from product, SDK, relative source path and explicit narrative kind. They have a null symbol and no API catalog row. SQLite schema/3 rejects older schemas unchanged before DDL; documentation references knowledge_records. Identity/1, content/1 and read-tools/2 remain unchanged. Recipe/runtime/parser/schema fingerprints and production capabilities are versioned together.

Known modern and legacy ownership wrappers preserve source order, multiple paragraphs, preformatted code whitespace (including CRLF), simple homogeneous nested lists, rectangular column-header tables, generic/positional documentation, API/implementation/deprecation note labels and original hrefs/labels. Offline locators distinguish local, external, escaping and empty hrefs without fetching links, guessing relationship edges or inventing anchors. Named @throws links and signature/deprecation links are retained too. Searchable text is derived by DocumentationPayload from its retained blocks, list items and tables.

The existing DTO cannot represent mixed nested list ordering, several separately nested lists within one item, numbered-list overrides, rich list items/cells, table spans, row headers or captions. These produce PARTIAL_UNSUPPORTED issues with source path/context and a CODE block labeled `unsupported HTML` containing owned HTML evidence. Unknown/ambiguous/empty narrative ownership reports explicit partial issues and does not fabricate a record. Finite source-size, traversal, payload and persisted aggregate admission guards bound work. Coverage denominators remain explicitly unknown pending Story 2.11.

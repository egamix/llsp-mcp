## Deferred from: code review of story-1.3 (2026-08-25)

- `BuildContext.forInputs` hashes normalized path strings (and, per Story 1.4, file content) but never resolves symlinks/junctions or normalizes case; two logically-identical input paths that differ only in casing (Windows/macOS) or via a symlink produce different digests/buildIds, breaking resume matching for that edge case. [`BuildContext.java:90-106,121-123`] — reason: pre-existing path-identity limitation; revisit if/when the five-hash recipe or Epic 6 hardening touches build identity again.
- `CheckpointStore.persist()` writes the checkpoint file directly rather than via a temp-file-then-atomic-move; a crash mid-write could leave a partially written/corrupt file. [`CheckpointStore.java:105-117`] — reason: largely mitigated once the `valueOf` parsing patch lands (a corrupt file then falls back to "start fresh" instead of crashing); a true atomic write is lower-priority hardening.
- No file-locking or other concurrency guard if two `cli ingest` invocations ran against the same inputs simultaneously — both would read/write the same checkpoint file. [`CheckpointStore.java`] — reason: no concurrent-invocation story exists yet and this is out of the stub's scope.
- `sealedInputDigest` deliberately excludes `--failure-policy` (AD-16 keeps it out of `BuildContext`/`IngestArguments`), so resuming a build with a different policy than the original invocation silently changes run behavior with no warning. [`BuildContext.java`, `IngestArgumentParser.java`] — reason: natural consequence of an intentional architecture choice (AD-16), not a defect — worth an operator-facing doc caveat if it comes up again.

## Deferred from: code review of story-1.4 (2026-08-25)

- `BuildContext.hashRootFiles`/`readAll` fully buffers each input file into memory via `Files.readAllBytes` and rehashes every byte of every file on every invocation, including pure resume-checkpoint checks — no streaming digest, no caching. [`BuildContext.java:90-119`] — reason: real for large model/javadoc trees but this story's Dev Notes scope synthetic fixtures only; revisit once input volumes become non-trivial.
- `Files.walk` in `hashRootFiles` doesn't follow symlinks, extending the existing Story-1.3-deferred path-identity limitation (symlinks/junctions never resolved) to file content walking, not just path digesting. [`BuildContext.java:95`] — reason: same root cause as the existing Story-1.3 deferred item on symlink/case handling.
- Neither the outer path-list join in `BuildContext.forInputs` (`String.join("\n", ordered)`) nor `relativeKey`'s backslash-to-slash conversion are length-prefix framed the way `ContentHashes`' multi-field hashes are — a filename containing a literal newline (or a POSIX path segment containing a literal backslash) could theoretically shift entries and collide two distinct input sets onto the same digest. [`BuildContext.java:79,109-111`] — reason: vanishingly unlikely for structured Javadoc/sample/model trees; same hardening technique as `ContentHashes` framing would apply if ever revisited.
- `ContentHashes.relationshipHash`/`toolchainFingerprint` null-tolerance is inconsistent (only `type` is checked; other fields silently accept null) — but there are no real callers yet: records/edges don't exist per this story's own scope boundary, and `toolchainFingerprint` is only ever invoked with hardcoded non-null stub constants today. [`ContentHashes.java:92-105,138-152`] — reason: revisit once Epic 2/3 wires real callers and the actual nullability contract is known.
- No formal `identityFields`-per-entity-type registry (AD-22) — currently just a caller convention. [`ContentHashes.java:65-79`] — reason: out of scope until real entity types exist (Epic 2+).
- `IngestionReport` has no schema/report-version field, and `ResolutionSummary` has no invariant tying its totals to its group sums. [`IngestionReport.java:52-79`] — reason: speculative hardening for a structure that's currently always zero/empty; revisit once Epic 2/3 populates real data.
- TOCTOU race in `hashRootFiles`: a file deleted between being listed by `Files.walk` and read by `Files.readAllBytes` crashes the whole run via an uncaught `UncheckedIOException` rather than a graceful `StageFailure`. [`BuildContext.java:90-106`] — reason: low-likelihood for a single local invocation over a stable input tree; consistent with the rest of the codebase not guarding against concurrent external mutation during a run.
